# Листи клієнтам через Resend — налаштування (10 хвилин, безкоштовно)

Resend не можна викликати прямо з сайту: їхнє API навмисно не приймає
запити з браузера. Тому між сайтом і Resend стоїть маленький безкоштовний
посередник — **Cloudflare Worker**. Він тримає ключ у себе (у код сайту
ключ не потрапляє взагалі) і сам збирає лист із даних замовлення.

---

## 1. Підтвердити домен у Resend

Щоб листи йшли з адреси `@reyter.men`, а не в спам:

1. [resend.com](https://resend.com) → **Domains** → **Add Domain** → `reyter.men`
2. Resend покаже DNS-записи (TXT і MX). Додайте їх там, де керуєте
   доменом reyter.men.
3. Дочекайтесь статусу **Verified** (зазвичай 5–30 хвилин).

> Поки домен не підтверджено, Resend дозволяє надсилати листи **лише на
> вашу власну пошту** — цього досить, щоб протестувати, але не для клієнтів.

## 2. Створити ключ

Resend → **API Keys** → **Create API Key** → права **Sending access**.
Скопіюйте ключ (показується один раз).

> Якщо ключ колись світився в переписці чи скріншоті — створіть новий,
> а старий видаліть. Ключ дає право надсилати листи від вашого домену.

## 3. Створити Worker

1. [dash.cloudflare.com](https://dash.cloudflare.com) → зареєструйтесь (безкоштовно)
2. **Workers & Pages** → **Create** → **Start with Hello World** → **Deploy**
3. Відкрийте створений воркер → **Edit code**
4. Видаліть увесь код і вставте вміст файлу [`worker.js`](worker.js) → **Deploy**

## 4. Додати змінні

У воркері: **Settings** → **Variables and Secrets** → **Add**:

| Назва | Тип | Значення |
|---|---|---|
| `RESEND_KEY` | Secret | ключ із кроку 2 |
| `MAIL_FROM` | Text | `REYTER <orders@reyter.men>` |
| `MAIL_BCC` | Text | `reyter.store1@gmail.com` — копія кожного листа вам |
| `ALLOW_ORIGIN` | Text | `https://reyter.men` |

> ⚠️ Після додавання змінних обовʼязково натисніть **Deploy** — без
> цього воркер їх не побачить і Resend відповідатиме
> «API key is invalid». Назва має бути точно `RESEND_KEY`,
> без пробілів на початку чи в кінці значення.

> Поки домен не підтверджено (крок 1), у `MAIL_FROM` залиште
> `REYTER <onboarding@resend.dev>`, а тестові листи надсилайте
> лише на пошту, якою ви зареєструвались у Resend.

### Як швидко перевірити воркер

Вставте адресу воркера в браузер. Має відповісти:

```json
{"ok":false,"error":"Method not allowed"}
```

Це нормально — воркер приймає лише POST. Якщо натомість бачите
помилку про `RESEND_KEY`, значить змінну не збережено.

## 5. Вписати адресу воркера в адмінку

Скопіюйте адресу воркера — вона виглядає як
`https://назва.ваш-акаунт.workers.dev`.

Адмінка → **Налаштування** → поле **Адреса Worker для листів** → вставте →
**Надіслати тест** → **Зберегти налаштування**.

---

## Листи з персональними промокодами

Той самий воркер надсилає й листи з персональними промокодами —
кнопка **«Надіслати на пошту»** в адмінці (розділ «Промокоди»).
Лист має той самий фірмовий вигляд: логотип на синьому, великий
код у рамці, розмір знижки, умови та кнопка «Перейти до покупок».

> Якщо ви розгортали воркер раніше — оновіть його код із
> [`worker.js`](worker.js) і натисніть **Deploy**, інакше кнопка
> відповість помилкою «Не вказано промокод».

## Що це дає

- Клієнт отримує фірмовий лист із логотипом REYTER на синьому тлі,
  номером замовлення, списком позицій, сумою та кнопкою «Відстежити замовлення»
- Лист приходить мовою, якою клієнт користувався на сайті
- Копія кожного листа — на пошту магазину (`MAIL_BCC`)
- **Ключ Resend ніколи не потрапляє в браузер** — його не можна вкрасти
  з коду сайту
- Воркер приймає лише дані замовлення й сам малює лист, тому надіслати
  через нього сторонній лист неможливо

Безкоштовних лімітів вистачає з запасом: Cloudflare — 100 000 запитів на
день, Resend — 3 000 листів на місяць.

Якщо воркер не налаштований, сайт працює як раніше: клієнт отримує
простий текстовий лист через FormSubmit.
