# Викладка: покроково

Сайт зібраний Next.js, тож у Cloudflare це **Worker**, а не тека
з файлами. Сторінки товарів статичні, але каталог перечитується
раз на хвилину — саме тому потрібен воркер: публікація з адмінки
доходить до покупця сама, без перезбірки.

## Як розкладені адреси

| Адреса | Що віддає | Хто роздає |
|---|---|---|
| `reyter.men/` | магазин | воркер `reyter-site` |
| `reyter.men/new/*` | переадресація 301 на нові адреси | воркер `reyter-site` |
| `www.reyter.men/` | переадресація 301 на голий домен | воркер `reyter-site` |
| `admin.reyter.men/` | адмінка з кореня | воркер `reyter-site` |

Магазин зібраний без `basePath` — усі його адреси лежать у корені
домену. 14.08.2026 він замінив собою попередній сайт: маршрути
воркера тепер `reyter.men/*` і `www.reyter.men/*`, тобто весь
домен.

> **Старі адреси `/new/*` лишаються живими назавжди.** Воркер
> переадресовує їх 301 на нові — `worker-entry.ts`. Прибирати цю
> переадресацію не можна: на неї ведуть листи покупцям, пошукова
> видача і, найдорожче, вже виставлені рахунки Monobank, у кожному
> з яких лежить `redirectUrl` на `/new/thanks`.

> **Адмінка має рівно одну адресу:** `admin.reyter.men/orders`.
> Всередині застосунку сторінки лежать під `/admin`, і цей шлях
> дописує воркер, не показуючи його в адресному рядку. Вкладки
> в `AdminBar` навмисно посилаються на короткі адреси: саме href
> задає те, що видно в рядку після кліку.

Кроки нижче йдуть **по черзі**. Після кожного є що перевірити.
Кожен відкочується назад, і до кроку 7 попередній сайт узагалі
не змінюється.

---

## Крок 0. Перевірити в себе, перш ніж кудись викладати

У терміналі:

```bash
cd /Users/kosmov/reyter/app
npm run cf:preview
```

Команда збере сайт і підніме **той самий воркер**, що поїде
в Cloudflare. Наприкінці вона надрукує адресу — щось на кшталт
`http://localhost:8787`.

Відкрити **`http://localhost:8787`** — магазин у корені.

- каталог відкривається, картинки на місці;
- клік по товару веде на його сторінку;
- кнопка **UA / EN** у шапці перемикає мову;
- у кошик додається;
- `/account` відкриває кабінет.

Зупинити — `Ctrl+C` у терміналі.

> Перевіряти саме `cf:preview`, а не `npm run dev`: `dev` — це
> Node, а в Cloudflare інше середовище. Різниця вже раз вилізла
> (див. коментар у `next.config.ts` про Firebase).

## Крок 1. Увійти в Cloudflare з терміналу

```bash
cd /Users/kosmov/reyter/app
npx wrangler login
```

Відкриється браузер зі сторінкою Cloudflare. Натиснути
**Allow** (Дозволити). Термінал скаже `Successfully logged in`.

Перевірити, що акаунт правильний:

```bash
npx wrangler whoami
```

Має показати вашу пошту й акаунт, у якому лежить `reyter.men`.

---

## Крок 2. Викласти воркер (домени НЕ чіпаємо)

```bash
cd /Users/kosmov/reyter/app
npm run cf:deploy
```

Це триває 2–4 хвилини. Наприкінці термінал надрукує адресу
воркера й перелік маршрутів. На технічній адресі магазин теж
у корені:

```
https://reyter-site.<ваш-акаунт>.workers.dev
```

**Запишіть її** — вона потрібна далі.

---

## Крок 3. Дозволити вхід із нової адреси у Firebase

Без цього кабінет і адмінка не відкриються: Google не пустить
вхід із незнайомого домену.

1. Відкрити <https://console.firebase.google.com>
2. Обрати проєкт **reyter-18d2c**
3. Ліворуч: **Build → Authentication**
4. Угорі вкладка **Settings**
5. Розділ **Authorized domains** → кнопка **Add domain**
6. Вписати `reyter-site.<ваш-акаунт>.workers.dev` (без `https://`)
7. **Add**

---

## Крок 4. Перевірити новий сайт наживо

Відкрити `https://reyter-site.<ваш-акаунт>.workers.dev`.

Пройти весь шлях покупця:

- каталог → картка товару → додати в кошик;
- у кошику видно категорію, розмір, суму;
- **Оформити замовлення** → вписати імʼя й телефон;
- у полі міста набрати «Львів» — має підтягнутись список
  з Нової Пошти, далі відділення;
- **не натискайте «Підтвердити»**, якщо не хочете створити
  справжнє замовлення. Якщо створите — його видно в адмінці,
  і його можна видалити.

Далі адмінка: `https://reyter-site.<ваш-акаунт>.workers.dev/admin`

(на власному домені вона відкриється просто з кореня —
переписування шляху робить `worker-entry.ts`)

- має зʼявитись екран входу;
- **Увійти через Google** вашим акаунтом;
- перевірити всі чотири розділи: Каталог, Замовлення, Склад,
  Промокоди.

Якщо десь порожньо або «немає прав» — переходьте до кроку 5,
правила бази ще старі.

## Крок 5. Оновити правила бази

Це окреме від викладки й потрібне в будь-якому разі: правила
посилено, і без них частина перевірок лишається тільки в браузері.

**Firestore:**

1. <https://console.firebase.google.com> → проєкт **reyter-18d2c**
2. Ліворуч: **Build → Firestore Database**
3. Угорі вкладка **Rules**
4. Виділити **весь** текст у полі й видалити
5. Відкрити файл `/Users/kosmov/reyter/new/firestore.rules`,
   скопіювати **все** й вставити
6. Натиснути **Publish**

**Storage** — те саме:

1. Ліворуч: **Build → Storage**
2. Вкладка **Rules**
3. Замінити вмістом `/Users/kosmov/reyter/new/storage.rules`
4. **Publish**

Після цього перезавантажити адмінку й перевірити, що каталог,
замовлення й склад читаються.

## Крок 6. Перевірити маршрутизацію за доменом

Адмінка має відкриватись із кореня `admin.reyter.men`. Перевіримо
це на тимчасовому піддомені, не чіпаючи справжній.

1. <https://dash.cloudflare.com>
2. Ліворуч: **Workers & Pages**
3. У списку знайти **reyter-site** → відкрити
4. Вкладка **Settings**
5. Розділ **Domains & Routes** → кнопка **Add** → **Custom domain**
6. Вписати `admin-next.reyter.men` → **Add domain**

Cloudflare сам створить DNS-запис (домен уже в нього). Зачекати
1–2 хвилини.

Відкрити `https://admin-next.reyter.men` — має одразу відкритись
**адмінка**, без `/admin` в адресі.

Додати у Firebase → Authorized domains ще й `admin-next.reyter.men`
(як у кроці 3), інакше вхід не спрацює.

## Крок 7. Перемкнути адмінку на новий сайт

З цього кроку починаються зміни, які видно назовні. Магазин ще
лишається старим.

**7.1. Прибрати домен зі старого проєкту**

1. **Workers & Pages** → відкрити **старий проєкт Pages**
   (той, що роздає `reyter.men` зараз)
2. Вкладка **Custom domains**
3. Навпроти `admin.reyter.men` → **⋯** → **Remove domain**

**7.2. Додати його новому воркеру**

1. **Workers & Pages** → **reyter-site** → **Settings**
2. **Domains & Routes** → **Add** → **Custom domain**
3. Вписати `admin.reyter.men` → **Add domain**

Зачекати 1–2 хвилини, відкрити `https://admin.reyter.men`.

`admin.reyter.men` уже є в Authorized domains Firebase — ви
додавали його раніше.

**Якщо щось не так:** повернути домен старому проєкту тими самими
двома діями у зворотному порядку.

---

## Крок 8. Перевірити адреси після переїзду

Корінь домену тепер за воркером. Старий проєкт Pages лишається
живим, але трафіку більше не бачить: маршрут воркера за шляхом
має перевагу над кастомним доменом Pages.

**8.1.** **Workers & Pages** → **reyter-site** → **Settings** →
**Domains & Routes**: у списку мають бути `reyter.men/*`,
`www.reyter.men/*` і `admin.reyter.men` (custom domain).

**8.2.** Перевірити:

- `https://reyter.men` — магазин;
- `https://reyter.men/en` — англійська;
- `https://reyter.men/p/CRH-001` — сторінка товару;
- `https://reyter.men/new` — переадресація 301 у корінь;
- `https://www.reyter.men` — переадресація 301 на голий домен;
- `https://admin.reyter.men/orders` — замовлення.

**8.3.** Якщо колись прибиратимете старий проєкт Pages —
спершу переконайтесь, що в DNS зони лишається **проксійований**
запис для `reyter.men` і `www.reyter.men`. Маршрут воркера
працює лише там, де запит взагалі доходить до Cloudflare: разом
із кастомним доменом Pages може зникнути і сам DNS-запис, і тоді
домен перестане відкриватися зовсім.

---

## Крок 9. Дозволити новому сайту слати замовлення

Воркер сповіщень пускає запити лише зі знайомих адрес.

1. **Workers & Pages** → воркер сповіщень (той, що з Telegram
   і Resend; його адреса вписана в адмінці → Налаштування)
2. **Settings** → **Variables and Secrets**
3. Знайти `ALLOW_ORIGIN` → **Edit**
4. Переконатись, що там через кому є:
   `https://reyter.men,https://www.reyter.men,https://admin.reyter.men`
5. **Save** → обовʼязково **Deploy**

Перевірити: оформити тестове замовлення на сайті й подивитись,
чи прийшло повідомлення в Telegram і лист на пошту.

---

## Крок 10. Прибрати за собою — не одразу

**Старий проєкт Pages не видаляти щонайменше тиждень.** Якщо
щось випливе, повернути домен назад — це дві дії в панелі.

Через тиждень спокійної роботи:

- прибрати тимчасовий домен `admin-next.reyter.men`;
- прибрати його ж із Firebase → Authorized domains.

Сам старий сайт у корені репозиторію (`index.html`, `new/`)
краще лишити: після публікації адмінка оновлює в ньому
`new/js/data.js` як резервну копію каталогу.

## Якщо щось пішло не так

**«Не вдалося завантажити» в адмінці** — правила бази ще старі
(крок 5) або ви увійшли не тим акаунтом.

**Вхід через Google не працює** — домен не доданий у Firebase →
Authentication → Settings → Authorized domains.

**Замовлення оформлюється, але повідомлень немає** —
`ALLOW_ORIGIN` у воркері сповіщень (крок 9), і після зміни
обовʼязково **Deploy**.

**Перевірити локально окремий домен.** `wrangler dev` підставляє
хост із маршрутів у `wrangler.jsonc`, тож заголовком `Host` його
не підмінити. Потрібен явний прапорець:

```bash
npx wrangler dev --local --host reyter.men        # магазин
npx wrangler dev --local --host admin.reyter.men  # адмінка
```

**Сторінка віддає 500** — подивитись живі логи:

```bash
cd /Users/kosmov/reyter/app
npx wrangler tail reyter-site
```

І тримати вкладку з сайтом відкритою — помилка зʼявиться
в терміналі.

**Треба терміново повернути попередній сайт** — Cloudflare →
старий проєкт Pages → **Custom domains** → додати `reyter.men`
і `www.reyter.men`, і лише ПОТІМ Workers & Pages →
**reyter-site** → Settings → Domains & Routes → прибрати
маршрути `reyter.men/*` і `www.reyter.men/*`.

Саме в такому порядку. Якщо спершу зняти маршрути, домен лишиться
без нічого: попереднього сайту в корені більше немає, і зняття
маршруту не повертає його — воно лише прибирає магазин.
